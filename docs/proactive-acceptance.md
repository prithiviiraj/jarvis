# Local event-driven persona judgment

Experimental opt-in addition to camera/app groundwork. Enable local sensing, load exactly one LM Studio chat model and start its localhost server, then separately consent to let the local persona read presence/app context. Optional spontaneous JARVIS voice requires its own checkbox and existing verified voice assets/headphones. No microphone starts from this control. Cloud models, screen/game vision and tools are excluded. Gaming mode suspends local model judgment.

Only new presence/app events prompt the model. The model returns strict JSON speak/silence; no scheduled reminder text is generated by code. Quiet00:00-07:00, minimum120s between requests, maximum12 requests per rolling hour and a single in-flight request are suppression gates. Events suppressed by quiet/busy/cooldown are dropped, not replayed later. Presence is not identity/sleep/health; wellness remarks are optional, not diagnoses. App titles remain untrusted data. Replies are limited to35words/240characters and invalid results fail quiet. No cloud-capable router is accepted. Real model behavior and prompt-injection resistance require adversarial/laptop acceptance, not only unit tests.

Stop/Pause/close revokes dispatch, discards late answers, stops output and clears context. Observation changes during generation discard a stale reply. Existing voice conversation suspends proactive requests. No note persistence or independent actions. Local-only removes API billing, not CPU/GPU/power cost. This local phase is intentionally unavailable during gaming rather than silently using paid/cloud slots.

Test: defaults off, independent context/audio consent, new events only, model-chosen silence and short comment, invalid JSON, cloud-router rejection, timeout/no fallback, quiet/busy/gaming suppression, source changes, Stop during model/synthesis/speech, no late save/speech. Validate actual LM Studio quality/latency and JARVIS output on laptop. Full proactive camera vision, identity and24/7soak remain open.
